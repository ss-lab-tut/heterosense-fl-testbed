# v2.1 設計メモ — KL-1（真値の決定的漏洩）の解消

> **状態: 設計のみ。実装は smart room 実測誤差分布の取得後**（確率モデルを実データで較正するため）。
> 背景: `KNOWN_LIMITATIONS.md` KL-1／`experiments/fl_observation_layer/AUDIT_D3.md`。

## 問題（KL-1 再掲）
v2.0 は真の離床時刻 `exit_s` に motion バーストを**厳密同一秒**で立て（`_b2t.py`）、PIR は不応期外なら
**その整数秒に決定的発火**（`_pir_model.py`, report_period 量子化のみ）。よって発火列は真値の決定的
変換であり、十分表現力ある観測モデルは逆変換して見かけ上の高 timing 精度を出す＝timing 学習上限の
評価が無効。

## 修正方針（決定論を2点で切る・v2.1 ノブ, 既定 off＝v2.0 挙動を保持）

### F1. exit-motion 開始のジッタ（`_b2t.py::generate_b2t_night`）
起き上がり motion の開始を、真の `exit_s` からオフセット `δ ~ Jitter` させる:
```
onset = exit_s + round(rng.<dist>(...))     # δ: 起床動作の遅れ・揺らぎ
motion[onset : onset + mv] = True
# truth は exit_s のまま（ラベル＝真の離床。観測はそこから δ ずれる）
```
- 意図: ラベル `exit_s` と観測可能な motion 開始を**分離**。学習モデルは δ の分布までしか復元できず、
  timing 誤差の**下限が δ の分散で決まる**＝逆変換不能に。
- 帰宅側 motion にも同型のジッタを適用。

### F2. 発火の確率的欠落（`_pir_model.py::observe_sequence`）
各 moving 秒の発火を確率 `p_fire<1` に（不応期に加えて）:
```
if rng.random() >= p_fire:   # 確率的ミス（真の PIR の検出漏れ・視野/姿勢依存）
    continue
```
- 意図: 「motion→発火」の決定性を崩す。exit の起床動作が**常には発火しない**ため、最近傍発火が
  ラベル秒に張り付かない。既存 `PIRSensor.blind_spot_rate`（v2.1 coverage hook）と統合可能。

### 較正（実装の前提・重要）
`Jitter` の分布と `p_fire` は**推測でなく smart room 実測**で決める:
- smart room で実 PIR 生イベント列＋ビデオ/床圧 ground-truth を取得（裁定2, REPORT §9）。
- 真 exit への**最近傍発火距離分布**を実測 → `Jitter`（δ の分布）に較正。
- 起床動作あたりの**発火取得率**を実測 → `p_fire` に較正。
- sim-to-real 表（REPORT §5）に「exit ジッタ＝較正済（smart room, 出所）」を追記。

## 後方互換・回帰
- v2.1 ノブ `ClientConfig.exit_jitter_dist=None, p_fire=1.0`（既定）で v2.0 と byte 一致。
  `test_v1_compat` 同型の回帰テストを追加（既定設定で v2.0 結果不変）。
- 既定 on にはしない（旗艦 v2.0 結果の再現性を保つ）。研究D の再評価時に明示的に有効化。

## 検証（修正が効いた判定）
- 修正後、report_period=0 でも **exit 最近傍発火 gap が 0 に張り付かず** `Jitter` 分布を反映。
- D-3 相当の学習が **δ の分散を下回る timing 精度を出せない**ことを確認（逆変換不能＝KL-1 解消）。
- これを満たして初めて、observation-model 学習の timing 実性能を sim で論じてよい。
